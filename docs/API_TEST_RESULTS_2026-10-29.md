# API 연동 테스트 결과 — 2026-10-29

실제 배포 서버의 읽기 요청과 개발용 모의 서버의 화면 테스트를 구분해 기록했다. 실제 회원 데이터 변경, 가입 승인/거절, 정산 생성은 배포 서버에 실행하지 않았다.

## 실제 배포 서버에서 확인한 차단 문제

| 요청 조건 | 결과 | 해석 |
| --- | --- | --- |
| 인증/Origin 헤더 없는 지역·모임·정산·가입 신청 GET | 401, AUTH401_1, `인증이 필요합니다.` | 인증 정보가 없는 요청의 거부이며 로그인 성공/실패를 검증한 결과가 아님 |
| Origin `http://localhost:5173`의 정산 GET 사전 요청 | 403, `Invalid CORS request` | 로컬 Origin의 CORS 거부 |
| Origin `http://127.0.0.1:5173`의 정산 GET 사전 요청 | 403, `Invalid CORS request` | IP 형식 개발 Origin도 거부 |
| Origin `http://localhost:5173`의 정산 실제 GET | 403, `Invalid CORS request` | OPTIONS만의 문제가 아니라 실제 읽기도 차단 |

현재 개발 기본 API 주소는 `https://jeonggyul.duckdns.org/api/v1`이다. API 모드로 실행하면 로컬에서 교차 출처 직접 호출이 발생한다. 이 조건에서는 브라우저에 네트워크/CORS 오류가 나타날 수 있다. 백엔드의 허용 Origin·메서드·헤더·credentials 설정 검토 또는 프런트 개발 프록시 설계가 필요하다. 백엔드 코드는 수정하지 않았다. 운영 배포의 같은 출처 `/api/v1` 프록시는 별개 경로이므로 이 결과만으로 운영도 CORS 실패라고 단정하지 않는다.

## 재현 후 로컬에서 수정한 프런트 버그

1. **응답 형식이 다르면 화면이 중단됨**
   - 가입 신청 목록에 `items`가 없는 HTTP 200 응답을 주면 `Cannot read properties of undefined (reading 'map')` 재현.
   - 목록·상세와 모임 상세 응답을 검사하고 `INVALID_API_RESPONSE` 오류로 변환.
   - 같은 시나리오에서 화면이 유지되고 한국어 오류·재시도 버튼이 표시됨을 확인.
2. **취소된 요청에서 토큰을 재발급함**
   - 응답 도착 중 AbortController 취소 + 401 응답에서 원래 요청과 재발급 요청 총 2회 발생.
   - 비동기 단계 사이에 취소를 검사하도록 수정.
   - 회귀 테스트에서 원래 요청 1회만 발생하고 재발급하지 않는 것을 확인.
3. **네트워크 오류에 영문 기술 문구만 표시됨**
   - `Failed to fetch` 그대로 노출되는 것을 화면에서 확인.
   - `NETWORK_ERROR`와 한국어 연결 안내로 변환. 요청 취소는 네트워크 오류로 바꾸지 않음.
   - 연결 복구 후 화면의 재시도 버튼으로 목록이 다시 표시됨을 확인.

## 모의 서버에서 통과한 화면 테스트

실제 React 화면을 `/scripts/api-qa.html`에서 실행했다. 모의 fetch는 이 개발 페이지 안에서만 사용하며 운영 엔트리에서 불러오지 않는다.

- 정산: 목록 → 상세, 3,334 + 3,333 + 3,333원 표시, 납부·미납·환불 상태.
- 정산: 다음/이전 페이지(1/2 ↔ 2/2), 빈 목록.
- 가입 신청: 승인 확인 → 성공 안내 → 목록 재조회 → 빈 목록.
- 가입 신청: 거절 사유 입력 → 확인 → 성공 안내 → 목록 재조회.
- 두 화면 모두: 빈 목록, 401, 403, 네트워크 실패, 잘못된 응답 형식에서 화면 중단 없이 안내.
- 네트워크 실패 → 모의 응답 복구 → 화면 재시도로 목록 복구.

## 자동 검사

`node scripts/check-api-contracts.mjs` 통과:

- URL·쿼리·정산 대상 본문·승인/거절 본문
- 인증 쿠키와 CSRF 헤더 전달
- 잘못된 응답 형식과 null 모임 상세 거부
- 취소된 조회의 불필요한 재발급 방지
- 재발급 성공 후 원래 요청 재시도, 재발급 실패 시 무한 반복 방지
- 한국어 네트워크 오류 변환

TypeScript 검사, production build, `git diff --check` 통과. 단일 JS 청크가 500kB보다 크다는 빌드 경고는 남아 있다.

## 아직 확인할 수 없는 성공 흐름

- 실제 인증 쿠키와 해당 모임 권한이 있는 계정의 조회 성공.
- 실제 가입 승인/거절·정산 생성. 테스트용 계정/모임에서 별도 확인 필요.
- 정산 생성 화면: `group_member.id`를 얻을 회원 목록 API가 없어 현재 API 모드에서는 제한.
- 실제 내 모임 목록: 현재 배포 명세에는 목록 API가 없어 홈 카드가 로컬 데이터임. 로컬 샘플 ID가 서버 모임 ID와 맞지 않으면 403/404가 될 수 있음.

## 실행 방법

```sh
node scripts/check-api-contracts.mjs
npm run dev -- --host 127.0.0.1 --port 5177 --strictPort
```

개발 서버에서 `http://127.0.0.1:5177/scripts/api-qa.html`을 열어 응답 시나리오를 변경한다. 실제 로그인 쿠키나 운영 데이터를 테스트 픽스처에 넣지 않는다.
