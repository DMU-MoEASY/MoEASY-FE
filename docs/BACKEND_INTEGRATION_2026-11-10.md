## When2meet 변경의 핵심

- 모든 가용시간 투표는 날짜 열 × 연속된 30분 시간 행으로 표시한다.
- 개인 가능 시간은 초록색 칠하기/지우기, 전체 가능 시간은 참여 인원 히트맵으로 분리한다.
- 사각형 드래그는 드래그 시작 때의 선택에서 매번 재계산해 축소·역방향에서 잔상이 남지 않는다. 키보드 선택과 터치 스크롤 전환도 제공한다.
- 기기 내 예전 후보형 투표는 기존 선택·응답을 보존하면서 연속 시간표로 표시한다. 별도 후보 버튼식 투표 UI를 만들지 않는다.
- 기기 내 추천은 한 칸의 최다 인원만 보지 않고 모임 길이에 걸친 동일 참여자 교집합을 구한다. 서버 모드에서는 백엔드가 반환한 연속 구간 추천과 최신 token을 사용한다.
- 서버 화면은 화면 복귀 및 60초 간격 REST 재조회로 갱신한다. 로컬 미저장 선택은 재조회로 덮어쓰지 않는다.
- 원시 WebSocket `/ws/schedules/{scheduleId}/availability`는 이번 배포에서 연결하지 않는다. Vercel 프록시 인증 쿠키와 백엔드 WebSocket의 동일 출처/인증 전달 경로를 먼저 확정해야 한다. 따라서 즉시 실시간 동기화 완료라고 표현하지 않는다.
- 기기 내 임시 투표는 명시적으로 분리한다. 서버 404를 임시 투표 저장 성공으로 바꾸지 않는다.

## 검증과 한계

- `node scripts/check-new-backend-contracts.mjs`: 신규 경로·본문·쿠키/CSRF, 모임 회원 ID와 계정 ID 구분, expectedVersion, 672칸 최대 범위, 예전 응답 보존, 연속 구간의 동일 참여자 교집합 확인.
- `node scripts/check-api-contracts.mjs`: 기존 정산·가입 신청·인증/재발급 회귀 검사.
- 로컬 React 모의 API 화면: 사각형 드래그로 2칸→8칸, 응답 저장, 서버 일정 수정 폼의 설명·종료·주소, 실제 모임 회원을 이용한 10,000원/3명 미리보기(3,334/3,333/3,333), 금액 변경 시 미리보기 무효화, OCR 진입/취소 시 작성값 보존, 마스킹 계좌·거래 조회, 404 대기 안내 확인.
- 모바일 390px 및 데스크톱 그리드 배치를 확인했다. QA 엔트리는 DEV 전용이고 운영 빌드에 포함하지 않는다.
- 실제 운영의 `GET /api/v1/groups/2/schedules`는 브라우저 인증 만료로 `AUTH401_1`을 반환했다. 실계정 조회·일정 생성·납부 변경·출석 확정·계좌 동기화를 성공했다고 주장하지 않는다.
- 실제 서버 쓰기는 수행하지 않았다. 열린 백엔드 PR은 백엔드 팀의 검토·병합·배포 후 재검증해야 한다.

## 내 프로필 표시 점검

- 현재 배포 Swagger에는 내 프로필 GET이 없다. `POST /members/me/onboarding`은 존재하지만 프로필 조회 용도로 사용할 수 없다.
- 모임 회원 목록 `GET /groups/{groupId}/members`에서 로그인 세션의 `memberId`와 일치하는 행의 닉네임만 사용한다. `groupMemberId`나 첫 번째 회원을 본인으로 취급하지 않는다.
- 가입 모임이 없거나 조회할 수 없으면 계정별 로컬 닉네임, 없으면 `회원 #ID`를 표시한다. 공유 레거시 프로필과 정확히 일치하는 샘플 프로필은 실제 계정에 복사하지 않는다.
- 소개·지역·관심사 편집은 로컬 저장이다. 프로필 사진·서버 활동 통계 연동은 미구현이다.
- 전체 프로필 복원을 위해 백엔드에 본인 프로필 GET이 필요하다. 제안 응답: memberId, nickname, statusMessage, regionCode/regionName, categoryCodes, profileImageUrl.
- 검증: 타입 검사, 프로덕션 빌드, 프로필 저장 정책 검사 및 개발 전용 모의 화면에서 본인 행 매칭·조회 실패·계정 전환 확인. 실제 로그인 계정의 운영 데이터 조회 성공은 별도 확인이 필요하다.
