# FE API 가이드 반영 결과 (2026-11-11)

기준 문서: [정산 납부·회원 목록·모임 계좌 API 가이드](https://futuristic-turner-09f.notion.site/FE-API-414bf07f90e3806084f0f703a593eebe)

Notion 커넥터는 접근하지 못했지만 공개 브라우저 문서 전체를 확인했다. 배포 `/v3/api-docs`, 백엔드 develop의 `docs/api/bank.md`, `availability.md`, `schedule.md`와 대조했다. 비밀정보·실회원 데이터·Notion 원문 전체는 이 문서에 저장하지 않는다.

## 반영 범위

| 요구사항 | 프런트 처리 |
| --- | --- |
| 쿠키/CSRF·ID 구분 | 기존 공통 apiClient 유지. 정산 대상은 groupMemberId, 본인 판별은 memberId |
| 회원 목록 변경 | 정산 생성의 SETTLEMENT400_2에서 회원 목록 재조회, 유효하지 않은 선택 제거 및 미리보기 무효화 |
| 정산 진행률·개인 납부 현황 | 목록의 완납/대상 인원·납부액, 상세의 총 납부·잔액과 개인별 청구·납부·잔액 표시 |
| 납부 등록 | OPEN/PENDING 및 운영진에게만 노출. 잔액 기본값·상한, 양의 정수, 선택 입금 시각·미래 차단, 최신 expectedVersion 사용 |
| 납부 취소·이력 | OPEN의 PENDING/PAID 청구에 유효 PAYMENT 기록만 취소. 사유, 처리자·시각, null 감사 필드 및 취소선 표시 |
| 변경 실패/불확실한 응답 | 자동 재등록 없이 상세·이력 재조회. 상세 재조회 실패 시 변경 UI 제거 |
| 계좌 연결·해제 | 운영진 폼·확인, 계좌 하이픈/공백 제거 및 은행·키 입력 검증. BANK404_1만 미연결 빈 상태로 취급 |
| 거래 동기화 | NH/KB/WR/IBK의 개인·사업자 입력과 SH의 인터넷뱅킹 입력 분기. 31일·오늘 제한, 90초 대기, 중복 요청 차단 |
| 은행 인증정보 | React 메모리에서만 처리. 요청 결과와 무관하게 인증 입력 초기화, 닫기·화면 이탈로 제거. 영구 저장·로그 출력 없음 |
| 호출 제한·오류 | nextSyncAt 대기 표시. 429 자동 재시도 없음. 시각을 확인할 수 없으면 30분 보수적 대기. 인증·외부 장애·서버 설정 오류 안내 |
| 계좌/거래 조회 | 마스킹 계좌번호·운영진 입력 예금주 구분, 마지막 동기화, 입출금·음수 잔액·페이지 이동 |
| 화면 연결 | 모임 회비 → 서버 계좌/거래 및 정산 목록. 기기 내 기존 회비 기록은 별도 진입으로 보존 |
| 출석부 | UNRECORDED 응답 수용, 쓰기에서는 제외. 미기록 선택·회원 닉네임, 미저장 시 집계 완료 차단. 일반 회원에게 운영진 버튼 숨김 |
| 가용시간 관리 | 운영진 설정 변경·재개방, OWNER 삭제. 입력은 변경 가능한 5개 필드만 전송. 없는 일정과 없는 투표 구분 |
| 갱신 | REST 복귀/60초 조회 유지, 일시 오류 지수 재조회. 선택 초안 보존. 옵션으로 WebSocket 수신·병합·재연결 구현 |

## 검증

- `npx tsc --noEmit`, `npm run build`
- `node scripts/check-fe-api-management.mjs`: 미기록 출석 처리, 은행별 입력 분리와 날짜/키 검증, 요청 JSON/쿠키/CSRF, 429 재시도 없음, 가용시간 설정의 읽기 전용 필드 제외
- 기존 API·신규 계약·인증 진입·계정 격리 검사
- DEV 전용 `scripts/fe-management-qa.html`: 계좌 연결→동기화→대기→해제, 신한 인증 폼, 429 후 입력 초기화와 5분 대기, 부분 납부 4,000원/잔액 6,000원, 409 후 재조회, 취소 이력, 일반 회원 권한, 미기록 출석 조회·변경·저장, 시간표 설정 폼
- 390px 모바일 납부 이력 레이아웃 확인. 모의 요청만 사용했고 QA 엔트리는 프로덕션 번들에서 제외한다.

## 남은 외부 의존성

- 실제 운영 계정의 역할별 조회·저장과 실제 은행 인증은 미검증이다. 이전 운영 읽기 요청은 비로그인 상태에서 AUTH401_1을 반환했다. 실제 납부 변경·은행 호출을 테스트 성공으로 표현하지 않는다.
- WebSocket은 `VITE_AVAILABILITY_WS_BASE_URL`을 인증 쿠키가 전달되는 검증된 `/ws` 루트로 설정해야 한다. Vercel의 REST rewrite가 Upgrade를 지원한다고 가정하지 않는다. 기본값은 비활성이며 REST 조회를 유지한다. 운영 소켓 연결 성공은 미검증이다.
- 내 프로필 GET, 추천 피드(#41), 자동 거래-납부 매칭·실제 송금·정산 수정/마감 등은 배포된 계약 또는 서버 지원이 필요하다.
- 기존 FE PR #40의 서버 온보딩 작업은 별도 PR로 유지했다.
- 백엔드 소스·설정·브랜치를 수정하거나 병합하지 않았다.
