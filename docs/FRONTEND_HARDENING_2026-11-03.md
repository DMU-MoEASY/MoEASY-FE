## 데이터 표시 원칙

- 로컬 모드의 기존 예시·저장 자료는 삭제하지 않는다.
- API 모드는 계정별 별도 모임 저장소를 사용한다. 이 앱에서 서버 생성이 성공한 `source=api`, 현재 ownerMemberId 기록만 표시한다. 기존 혼합 목록이나 다른 계정 자료를 서버 모임으로 추정하지 않는다.
- 현재 서버의 내 모임 목록 API가 없으므로 이 기기에서 만든 모임만 보인다는 안내를 표시한다. 모임이 없어도 생성 화면으로 진입 가능하다.
- 실제 검색·알림·주변 번개 API가 없는 화면은 샘플을 실제 정보처럼 표시하지 않는다. 장소 검색은 계속 이용할 수 있다.
- 서버에서 확인할 수 있는 직접 모임 URL은 로컬 캐시에 없어도 조회한다. 없으면 404 안내와 목록 복귀를 제공한다.
- API 모드의 신규 일정·채팅·회비·게시글은 샘플로 채우지 않고 빈 기록에서 시작한다. 기기 내 기록임을 표시한다. 멤버·사진 API 미제공 화면은 준비 상태를 표시한다.
- 실제 회원 수·잔액·납부 결과로 오인할 하드코딩 수치와 로그인 화면의 근거 없는 이용자 수를 제거한다.

## 인증과 오류

- 동시 만료 조회는 하나의 토큰 재발급 요청을 공유한다.
- 재발급의 인증/권한 실패 또는 재시도 후 401이면 로그인 상태를 해제하고 소셜 재로그인 안내를 표시한다. 작성 중인 로컬 기록을 삭제하지 않는다.
- 일반 네트워크 장애·모임 권한 거부는 로그아웃시키지 않는다.
- 재발급 성공 후 정상 조회를 재시도하며 취소된 요청은 재발급을 시작하지 않는다.
- 화면 지연 로딩과 API 조회 중에는 고정 메뉴를 유지하고 내용 영역에 로딩 상태를 표시한다.
- 코드 청크 로딩/렌더 실패는 전체 빈 화면 대신 새로고침 안내를 표시한다.
- 403/404를 구분해 권한 확인/목록 복귀를 안내한다.

## 로딩 최적화

지도, 상세, 채팅, 정산, 일정/시간표, 마이페이지, 탐색, 온보딩, 보조 화면을 필요한 시점에 불러온다. 사이드바·헤더는 로딩 경계 밖에 유지한다.

직전 빌드의 초기 메인 JS 548.93kB에서 약 396kB로 감소(약 28%). gzip은 164.41kB에서 약 126kB로 감소. 이는 초기 메인 파일 비교이며 전체 앱/PWA 선캐시 다운로드 감소를 뜻하지 않는다. 이번 빌드에서는 500kB 청크 경고가 해소됐다.

카드 전환은 상세 모듈과 대표 이미지가 준비되는 시간을 제한해서 기다린 뒤 캡처한다. 로딩 실패는 오류 화면으로 처리한다.

## 검증

- `node scripts/check-frontend-hardening.mjs`: 계정/샘플 분리, 동시 재발급 1회, 만료 안내 중복 방지, 네트워크/권한 오류 시 로그인 유지.
- 기존 인증 진입 및 API 계약 검사 통과.
- TypeScript, production build, diff 검사 통과.
- 개발용 모의 서버에서 실제 App을 열어 다음을 확인:
  - API 표시 대상 외 샘플·다른 계정 모임이 숨겨짐.
  - 없는 모임 404 안내/복귀.
  - 네트워크 장애는 로그인 화면으로 보내지 않고 재시도 표시.
  - 만료 응답은 로그인 화면과 한국어 재로그인 안내.
  - 탐색·알림 준비 상태, 패널 닫기, 메뉴 유지 및 일정 빈 화면.
  - 390px 모바일 홈의 가로 넘침 없음, 고정 하단 메뉴 유지.
  - 수정 후 새 QA 방문의 브라우저 error 로그 없음.
- QA 픽스처는 개발 페이지에서만 로드되며 production 출력에 포함되지 않음. 실제 계정/회원 처리/정산 생성은 실행하지 않음.

## 여전히 백엔드 연동이 필요한 항목

내 모임/회원/권한 목록, 동 단위 지역, 일정·시간표 공유, 채팅·사진 공유, 알림/납부 상태 변경·발송. 서버 정산 생성은 회원의 실제 groupMemberId 목록이 준비돼야 화면을 안전하게 열 수 있다.

특정 계정의 과거 모임 자료를 숫자 ID로 추정해 복원하거나, API 실패를 로컬 성공으로 바꾸지 않는다.
